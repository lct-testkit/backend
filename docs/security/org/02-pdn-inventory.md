# Перечень обрабатываемых персональных данных

Основание: статья 19 Федерального закона № 152-ФЗ (перечень — часть мер по защите ПДн,
которые оператор обязан определить). Строится по коду (`app.db.models`), а не по памяти:
`backend/tests/test_pdn_inventory.py` разбирает модели SQLAlchemy и требует, чтобы каждая
колонка, похожая на ПДн по имени (`phone`, `email`, `snils`, `passport_*`, `birth_date`,
`first_name`/`last_name`/`middle_name`/`full_name`/`display_name`, `reg_*`, `*_dative`, `ip`,
`user_agent`, и явные добавки `contact_channels.value`/`deal_comments.body`/
`files.original_filename`) была либо упомянута здесь строкой `таблица.колонка`, либо исключена
в `NOT_PDN` с причиной. Срок хранения — ссылка на `app/core/config.py` (B6-6), не число
вручную; где это не применимо (хранится бессрочно/до запроса субъекта), указано явно.

## Технические данные (IP-адрес, User-Agent)

Привязаны к действию, а не являются самостоятельной целью обработки — используются для
расследования инцидентов безопасности (B6-2/B6-3/B6-12) и доказательства факта подписи.

## Что не удаляется никогда

`audit_log` и `signatures` защищены триггерами неизменяемости БД (миграции
`0002_identity_sprint`, `0007_signing_sprint`) — это неизменяемое юридическое доказательство,
а не рабочая копия ПДн. При удалении/обезличивании субъекта исторические записи этих таблиц
**не удаляются**, но ПДн в них перестают быть актуальными ссылками на живого человека (поле
`signer_display`/`changes` фиксирует состояние на момент действия, а не текущие данные
субъекта) — тот же подход, которым закон признаёт обязанности учёта и отчётности (п. 7 ч. 1
ст. 6 152-ФЗ) не противоречащими праву на уничтожение.

## Вне зоны этого репозитория

- база данных Keycloak (учётные записи, настройки TOTP) — отдельная инфраструктура, состав
  ПДн там не проверялся из этого репозитория;
- сессии в Redis (B6-11/`identity/session_store.py`) — токены и IP во время жизни сессии
  (idle timeout 30 минут, абсолютный TTL 12 часов), не персистентны;
- содержимое объектов в S3 (сами файлы, сканы паспортов, подписанные PDF) — состав
  определяется тем, что загрузил пользователь, и не перечисляется по колонкам;
- резервные копии PostgreSQL/SeaweedFS — срок хранения определяется циклом ротации
  (спринт D, вне этого пакета документов);
- логи приложения — проверяются отдельным тестом маскирования
  (`backend/tests/test_request_log_redaction.py`), не входят в этот перечень по колонкам БД.
